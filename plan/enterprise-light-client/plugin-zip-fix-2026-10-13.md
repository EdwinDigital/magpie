# ZIP 插件名称与供应商入口修复

## 问题分析

1. 原插件列表从本地目录名推导标题。ZIP 导入目录来自 `package.json.name`，
   企业插件包名可能包含用户 ID，不能直接当作友好的显示名称，也不能用正则猜测并删掉 ID。
2. 检查时企业包与本地配置的有效 `visibleProviders` 为空。已经加载、登录且有模型的插件
   供应商会被企业显示名单过滤；安装插件不等于授权该供应商显示。
3. 合并 main 后插件列表使用渐进式缓存：初始化返回时供应商描述可能还没加载完成。
   插件页面没有跟进该后台结果，名称、登录状态与配置入口可能停留在旧数据。

本次没有修改正在运行的应用、真实 Agent 配置、插件账号或凭据。

## 修复边界

- 增加可选的 `package.json.displayName`。ZIP 没有填写时优先使用已知供应商的友好名称；
  没有任何友好名称时仍回退真实包名，不猜测、篡改技术 ID。
- 列表、详情标题与删除确认保持同一名称。禁用或加载失败时仍可使用上次已知名称。
  安装 spec、ZIP 文件归属、provider ID、登录与企业应用身份均保持不变。
- 缓存快照同时返回已回答与待加载状态。插件页面仅在已有后台读取尚未完成时跟进元数据；
  不访问公开插件目录，不新建另一套供应商扫描，也不会在后台读取结束后持续轮询。
- 被企业名单隐藏的插件显示“可见供应商”入口，展开企业配置中的对应选择区。
  必须由用户勾选并保存，不自动放开名单。
- 可见且已经登录、有供应商卡片的插件显示“模型”，进入现有模型编辑器。
  隐藏供应商不提供会失败的登录入口。
- 企业配置读取复用同一个待完成请求。刷新候选项保留品牌草稿、勾选与输入焦点。
  窄窗口下操作按钮另起一行，避免挤压插件名称与隐藏原因。

可选的插件包字段示例：

```json
{
  "name": "company-provider-user-technical-id",
  "displayName": "Company Gateway",
  "main": "index.mjs"
}
```
