# 需求分析

## 1. 目标和范围

用户要求删减当前项目功能，适配企业级轻量使用场景。第一期以现有设置、供应商、插件和资源库为边界，新增企业配置，不重写客户端，不移除供应商实现或插件宿主。

明确保留其他既有页面和能力：Agent、网关、路由、用量、会话及原有设置。
后续 R11 明确要求按可见名单限制自动发现；不全局关闭订阅账号功能，
也不删除已有配置/凭据。遥测和网关授权不因可见名单改变。

## 2. 需求清单

| 编号 | 用户明确要求 | 预期结果 |
| --- | --- | --- |
| R1 | 设置新增企业配置，可定制应用名称和 logo，多处 magpie 和小鸟图标均需更新 | 页头、窗口、托盘及应用自有文案使用统一品牌来源；覆盖图4而非只改首页 |
| R2 | 配置可显示的供应商目录，默认 Copilot 和本机 Ollama；可选择插件和自定义供应商入口 | 供应商页面只显示默认供应商和勾选的名单；添加目录和其他回到该页面的入口遵循同一规则 |
| R3 | 可选择开放公开插件目录，默认不开放，只保留插件安装入口 | 默认不展示发现目录、公开推荐和公开搜索，仍可明确指定来源安装及管理已有插件 |

| R11 | 企业配置选择可见 Agent，默认六项；供应商和 Agent 列表可折叠并置于底部；未勾选不自动扫描 | 默认 Codex、Claude Code、Claude Desktop、VS Code、Copilot CLI、WorkBuddy，可修改或清空；复用模型列表的标题/搜索/行式组件，保存后更新展示和自动发现策略，不清理已有配置与凭据 |

## 3. 默认值

“明确”指用户直接规定；“建议”为便于设计而选择的初始值，开发前应确认。

| 配置 | 初始值 | 依据 |
| --- | --- | --- |
| 应用名称 / logo | 企业包继承发行品牌，独立通用构建回退原品牌；本机保存后使用运行时覆盖 | 建议：用户未提供具体企业名称及 logo；企业发行设计已获要求 |
| 默认供应商 | `copilot`、`ollama` | 明确；不包括 `ollama-cloud` |
| 额外供应商名单 | 空 | 建议：默认只展示两项 |
| 供应商页的插件入口 | 关闭 | 建议：用户要求可配置，但未指定初始值 |
| 供应商页的自定义供应商入口 | 关闭 | 建议：用户要求可配置，但未指定初始值 |
| 公开插件目录 | 关闭 | 明确 |
| 插件安装与已有插件管理 | 保留 | 安装为明确要求；管理为保留已有插件所需的兼容性设计 |
| 资源库 | 关闭 | 明确 |

企业轻量分支缺少企业配置时也使用上述精简默认值；企业包另加载已签名的发行档案。旧数据保留，不因默认收敛而清空。发行 profile 是构建配置，不是本机全局模式切换；若将来合并回通用版，仍需决定通用版的默认行为。

## 4. 企业配置页面

在设置二级标签新增“企业配置”，建议放在“常规”之后。纳入设置搜索、键盘导航和可定位的页签地址。

页面采用现有行式设置，按以下分组组织：

1. 应用品牌：名称输入、logo 预览、选择图片、恢复默认；显示不同表面的生效方式。
2. 供应商目录：默认两项固定显示；其余按订阅、API / 本地预设、已安装插件供应商、已有自定义供应商分组，可搜索和勾选。
3. 供应商入口：显示插件入口、显示自定义供应商入口两个独立开关。
4. 功能开放：公开插件目录、资源库两个独立开关，说明关闭目录不等于停止已有插件。
5. 保存区：保存、取消未保存更改、保存结果；存在待重启项时列出具体项目及两个操作。
6. 配置来源：企业包显示发行产品、版本 / profile revision、本机覆盖及恢复发行默认；提示本机品牌变更不会重写系统安装包。

采用显式“保存”而不是逐项自动写入，避免名称、图片和目录产生半保存状态。编辑中的预览不是全局生效；成功保存才对其他视图发布。导航离开脏表单遵循当前应用的放弃确认规则。

## 5. 供应商可见性语义

### 5.1 默认与勾选名单

- Copilot 指订阅 `copilot`；Ollama 指本机预设 `ollama`。不通过显示名称或 URL 子串判断身份。
- 默认两项在添加目录中始终可见、不可取消。未登录 Copilot、未添加 Ollama 时显示对应添加入口，不伪造已配置卡片或自动启动 Ollama。
- 其余供应商只有被明确勾选才进入可见名单；企业选择器自身必须能读取完整候选集，否则无法添加当前被隐藏的供应商。
- 已配置卡片、关闭中的卡片、添加目录、恢复已移除账号、迁移提示、本地配置发现 / 导入提示、搜索结果和 `?edit=` 深链接均使用同一展示规则。
- 只显示可见供应商的计数和空状态；不可在“关闭中”“搜索不到，去插件查找”等旁路再次列出隐藏供应商。
- 新插件安装后或新自定义供应商创建后不自动扩张名单；提示到企业配置勾选。明确选中的供应商，即使其快捷入口关闭，仍可管理既有可见卡片。

### 5.2 插件与自定义入口

- “显示插件入口”控制供应商添加区域通往插件页面的入口，不控制顶层插件页面，更不关闭插件宿主。
- “显示自定义供应商入口”控制新建自定义供应商入口，不代表所有已有自定义供应商自动可见。
- 插件供应商和自定义供应商是否显示，由名单决定；入口开关不能绕过名单。
- 白名单中的已迁移供应商仍走其插件实现；未迁移供应商仍走内置实现。不修改 `migrations.json` 或强制迁移。

### 5.3 展示收敛不等于授权

本期名单不自动停止既有请求，不删除凭据，不改供应商开关、不改路由组、不重写 Agent 配置。其他页面的模型、路由和历史记录继续准确反映实际运行状态，因此可能出现供应商页隐藏的供应商。

企业配置应明确说明：“仅控制供应商页面和添加目录的展示，不限制已有模型或网关访问。”若企业需要禁止未批准供应商的真实调用，须单独设计覆盖所有协议、备用路由、辅助模型、插件及 CLI 的授权机制；不能把隐藏 UI 宣称为这种安全控制。

## 6. 插件与资源库

- 插件安装表单始终是页面内容区第一块，公开目录开启或关闭、发现或已安装视图、加载中或加载失败时均可操作。
- 关闭公开目录时不请求公开推荐、GitHub 标签目录或 npm 搜索；隐藏发现标签、公开搜索和目录专属控件。公开目录打开后恢复发现能力。
- 手动安装仍支持 npm 包、`github:owner/repo` 和本地目录；网页模式保持无法选择服务器本地目录的既有边界。
- 已安装插件的状态、启停、更新、卸载、错误及符合名单的登录管理保留；没有插件时以安装说明替代“去发现页”的空状态。
- 关闭公开目录不等于离线模式。明确安装、已安装包更新、必要的迁移维护仍可能访问 npm / GitHub。
- 关闭资源库后，主导航、深链接、快捷跳转和 GUI 资源库 API 均不可进入；打开中的资源库编辑器如有未保存内容，先确认放弃再提交配置。
- 已有资源库文件、分配到 Agent 的 instructions / MCP / skills 和已配置 RTK 不删除、不卸载；现有底层同步行为不在此开关中自动改写。它是 GUI 模块开放开关，不是全面禁止 MCP / skills 的策略。

## 7. 品牌替换与生效边界

| 类型 | 范围 | 要求 |
| --- | --- | --- |
| 应用自有界面 | 页头、小鸟、页面标题 / favicon、设置常规与额度、关于、自有提示 / 空状态 / aria 文案、主窗口与托盘面板 | 统一使用企业名称和 logo，不能遗留独立硬编码 |
| 原生桌面表面 | 托盘图标和额度合成图、提示、打开 / 退出菜单、应用菜单及自有通知 | 纳入覆盖审计；根据真实平台能力热更新或标注待重启 |
| 第三方真实信息 | 插件 npm 包名、作者、原始说明、真实远程 Magpie、第三方应用中的固定 provider 名 | 保留真实身份，不能冒充企业自有产物；必要时解释来源 |
| 技术兼容标识 | CLI 命令、参数、`MAGPIE_*`、配置路径、localStorage key、协议头、模型 / provider ID、`magpie://`、模块路径 | 不替换字节；展示品牌与可执行示例分开处理 |
| 法律与来源 | LICENSE、第三方版权、上游仓库 / 文档 URL | 保留真实署名和可用链接；不把它们错误改成企业名称或 URL |
| 安装包表面 | Finder / 开始菜单 / 程序属性、bundle 展示名称、安装图标 | 已确认纳入企业发行设计；构建期替换并签名，平台发布新版本供员工下载 / 升级，不误报重启生效 |

保存成功后，供应商展示、入口、插件目录、资源库和 Web UI 品牌应实时更新。原生表面是否必须重启由逐平台验证决定，不预设所有品牌项都需重启。

名称建议校验：去除首尾空白，1–64 个 Unicode 字符，不含控制字符，作为文本渲染。logo 建议第一期接受 PNG / JPEG，限制 2 MiB 和解码像素上限，保存为应用自管的 PNG；SVG / URL logo 暂不支持，以减少脚本和外部请求风险。限制值是设计建议，不是用户追加要求。

企业发行档案和双平台方法见 [企业发行包与分发平台设计](enterprise-distribution-design.md)。未来平台配置生成不可变包内默认，员工本机显式覆盖优先作用于运行时展示；静态安装品牌变更通过新的受信发行包交付。平台默认配置不是供应商授权或远程强制策略。

## 8. 待确认与暂定方案

| 编号 | 事项 | 暂定方案 |
| --- | --- | --- |
| D1 | 系统安装包品牌已确认纳入；第三方 Agent 中固定 provider 名的替换仍需界定 | 企业档案在构建期生成系统安装品牌，本机设置只改运行时展示；技术 provider ID 和真实第三方信息继续保持 |
| D2 | 插件 / 自定义入口默认值未明确 | 均关闭；顶层插件安装与管理页保留 |
| D3 | 是否需要管理员锁定企业设置，或禁止非名单供应商的实际调用 | 本期不新增角色系统或网关授权，仅说明展示边界 |
| D4 | 本机覆盖是否跨设备同步，以及未来是否增加平台远程推送 | 企业默认与 logo 随发行包供全员下载；本机覆盖暂不跨机器同步，备份 / 同步恢复保留本机选择；远程推送另立需求 |

这些事项不阻塞文档补充；系统安装包发行设计已获明确要求，但开始实现前仍需确认签名主体、部署形态及 D3，不把建议的运营方案当作已批准发布。

## R12 免编译企业封装与安装身份

发行平台采用已审核的基础 runtime，按 profile 和上传 logo 生成企业安装包，无需再次编译 app。
企业版本与基础源码版本分开记录；macOS 包内资源、Windows PE 资源在签名前定制。
修改已签名安装包不是支持的配置方法；更改程序功能需要新的 runtime。

进程、CLI 和安装后的配置/缓存根目录使用配置中的文件系统安全名称 artifactSlug。
msai-client 对应 msai-client.app/Contents/MacOS/msai-client、msai-client.exe、
~/.config/msai-client、~/.cache/msai-client。展示名称的本机修改不移动身份或目录。
不占用公开版 magpie 命令、bundle/scheme、启动项、锁或配置；旧企业目录只允许显式迁移。
同时显式连接同一个外部 Agent 的配置仍需指定一个客户端负责，不承诺外部文件隔离。

## R11 自动扫描范围补充

未选择的 Agent 除安装/CLI/登录发现外，也不枚举其会话/调用文件和数据库；
启动历史预热、会话目录提示、用量原生会话扫描以及 WSL 缓存列表遵循同一策略。
既有网关账本和已知会话的显式读取不删除，也不成为新的权限授权规则。
