# 实施与验收计划

本分支已实现客户端与发行基础。以下清单区分已实现、待自动化验证和需要外部平台/证书的工作；实际命令与结果见 [验证记录](validation-report.md)。生产运营事项不作为已经部署或签名的证据。

## 1. 分阶段实施

### P0：范围与品牌审计

- [ ] 系统发行品牌已确认纳入；确认签名主体、发行形态和 D1–D4 剩余边界，尤其展示名单是否需要升级为实际授权。
- [x] 分类统计应用自有 magpie 文案、小鸟 / app / tray 图标、第三方信息及技术标识，建立覆盖清单。
- [x] 明确插件目录端点与已安装维护端点，核对候选供应商 ID、Preset 和 moved 映射。
- [x] 固化默认值、配置 schema、revision 和保存失败契约。

### P1：配置基础与企业页面

- [x] 添加企业配置模型、校验、锁内局部写入和缺省值。
- [x] 添加配置 / 完整候选集 / logo API，保持旧 settings 保存及备份恢复不覆盖新配置。
- [x] 在设置新增企业页，复用现有控件、搜索、脏表单和多语言机制。
- [ ] 验证图片异常、并发冲突、保存失败不发布，以及未引用资源的安全清理。

### P2：供应商页面收敛

- [x] 实现共用投影，覆盖启用 / 关闭 / 添加 / 搜索 / 导入 / 恢复 / 迁移提示 / 深链接。
- [x] 固定 Copilot、本机 Ollama 默认项；插件 / 自定义入口独立控制。
- [ ] 核验 moved 和未 moved 两条实际路径，维持 `unusedSub`、`replacedSub` 等现有规则。
- [x] 验证名单变化不修改凭据、供应商开关、模型目录、路由组或 Agent 配置。

### P3：插件与资源库

- [x] 将安装表单移到插件内容区第一块，搜索和刷新不重建输入。
- [x] 默认关闭公开目录；前端停止读取，后端在外部请求前拒绝公开目录访问。
- [x] 已安装维护与明确安装继续工作，空状态不引导到关闭的目录。
- [x] 默认关闭资源库，覆盖导航 / URL / GUI API；不移除已有 Agent 内容或底层库。
- [ ] 验证关闭过程中的异步晚到响应、安装中状态和未保存表单。

### P4：品牌与实时生效

- [x] 品牌 helper 覆盖自有文案与 UI；分类保留技术字节、法律署名和真实第三方信息。
- [x] boot 和 state 带有效配置；主窗口、面板、轻量窗口重建及网页刷新路径一致。
- [ ] 托盘额度合成、刷新和动画结束不能恢复旧小鸟或名称。
- [ ] 逐平台核验原生热更新能力，列出真实待重启项。
- [x] 实现不安装更新的配置重启，保留当前页面、处理在途请求及失败。
- [ ] 完成企业发行构建期名称 / 图标及签名兼容性验证，不用热更新代替。

### P5：回归与交付

- [x] 更新拥有变更契约的子系统参考及 GUI 测试说明。
- [x] 新测试在移除对应行为时真实失败，再恢复实现验证通过。
- [ ] 按仓库规范运行隔离 Go 测试、全量 GUI 测试及平台构建 / vet。
- [ ] 在沙箱应用实际验证主窗 / 托盘 / 重启和品牌，不连接或重启用户正在运行的 Magpie。
- [ ] 记录测试平台、版本、结果、未验证项和待确认项；本期不默认提交、推送或发布。

### P6：企业发行包基础

- [x] 实现发行 profile schema、品牌生成器及独立构建接口，按 [企业发行设计](enterprise-distribution-design.md) 的 E1 交付。
- [x] 包内默认 / 本机显式覆盖 / 恢复默认分层，升级时不覆盖本机选择。
- [x] 固定企业发行身份，隔离状态目录、启动项、单实例和协议，检测端口 / Agent 管理冲突。
- [ ] macOS 生成企业 `.app` / 图标 / plist 并签名、公证；Windows 生成企业 EXE 资源并签名。
- [x] 企业 feed 或手动更新显式选择；更新器支持企业包入口、身份 / 版本 / 签名校验，GUI 与 CLI 均不回到上游包。
- [ ] 执行 B01–B10 的本地发行基础场景，记录真实平台、证书与工具链验证范围。

### P7：未来分发平台

- [ ] 平台技术栈、登录、存储与签名运营方案获确认后，实现 E2 的 profile revision、队列、构建 / 签名隔离、审核与员工下载。
- [ ] 实现租户权限、短期下载授权、不可变产物、原子发布及完整审计。
- [ ] 按 E3 另行实现受信更新 / 回滚及可选受管安装，不默认加入客户端远程策略或遥测。

P6 可先用本地配置档案执行；P7 复用相同构建契约。本分支已有本地构建工具及分发 API；门户、SSO、耐久合规审计、云部署和证书运营仍为外部集成，不执行企业生产平台部署或证书配置。

## 4. 验证命令与环境

执行阶段按 [代码规范](../../docs/code-standards.md) 和 [插件参考的沙箱示例](../../docs/subsystems/provider-plugins.md#verification) 准备临时 HOME，先读取并固定 `GOPATH`、`GOMODCACHE`、`GOCACHE`。所有新进程必须清理或等待结束；不接触真实 Agent 配置、用户网关或真实凭据。

```sh
# 在隔离 HOME 和固定缓存准备完成后执行；使用 pipe 时启用 pipefail。
go test -tags nogui ./internal/settings ./internal/gui
go test -tags nogui ./...
go vet ./...
GOOS=linux go vet -tags nogui ./...
GOOS=windows go vet ./...
go build
GOOS=linux go build -tags nogui
GOOS=windows go build
make test-ui
```

还需对实际修改的 Go 文件运行 `gofmt -l`；GUI 全量测试覆盖 Chromium 与 WebKit，执行 en / zh 及 zh-TW / ja / de 校验。跨平台编译不等同于原生菜单、图标、通知或重启验证，后者需要对应平台实际运行。

测试记录包括：源码 SHA、命令、隔离方式、操作系统、浏览器引擎、语言 / 主题 / 尺寸、通过 / 失败及未执行项。失败不能被“main 也失败”掩盖；按仓库规范定位原因、修复或单独登记。

## 5. 本次记录

- 已实现：七项客户端需求、包内默认与本机覆盖、独立品牌/身份的构建工具、企业受信更新，以及供未来门户接入的租户分发 API。
- 原生差异：窗口、托盘、Dock 和网页可热更新；macOS 原生菜单项使用启动时名称，保存后准确提示重启；关于窗口使用实时名称/图标并保留包内版本与法律署名。
- 设计差异：本地自动导入入口整体关闭，避免引回隐藏供应商；上传的未引用图标不自动清理，避免删除另一窗口草稿；在途请求阻止立即重启并提示稍后重试，不自动强制中断。
- 更新隔离包含发布说明与下载镜像，不只是主 feed；企业包也不能抢占共享的 `magpie` PATH 命令。
- 未执行的生产事项：正式签名/公证、真实企业身份/门户/部署、受管安装、生产发布；Windows 原生环境测试按用户要求延期。
- 未提交、推送或发布。具体通过项、失败及未验证项以 [验证记录](validation-report.md) 为准。
